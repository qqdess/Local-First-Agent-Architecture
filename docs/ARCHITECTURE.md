# ARCHITECTURE

> 目标：让“生成”与“执行”解耦，让“完成”必须带证据。
> 本文只描述结构与不变量，不包含可执行实现。

## 2. 组件边界

| 组件 | 职责 | 明确不做 |
|---|---|---|
| Ingress | 接收消息、命令、事件 | 不做路由、不做执行 |
| Intent Classifier | 把自然语言映射为 intent + tier | 不决定具体 provider |
| Single Executor | 唯一路由与执行入口 | 不直接面向用户聊天 |
| Cloud Outsource | 语义解析、文本/代码草稿 | 不持有状态、不直接操作环境 |
| Local Model | 云端不可用时的兜底 | 不冒充“同等能力” |
| Evidence Gate | 校验结果、哈希、回读 | 不接受“口头完成” |
| Deterministic Action | RPA / 脚本 / 文件操作 | 不绕过不可逆操作审批 |
| Trace Ledger | 记录 trace、provider、耗时、证据 | 不做决策 |

## 3. 五条不变量

1. **单一执行器**：同一时刻只有一个执行入口，分类器只给建议。
2. **单一主账**：调度日志只有一份；其他日志是审计，不是决策依据。
3. **证据优先**：`ok=true` 必须带 `<EVIDENCE>`；缺证据视为失败。
4. **合同完整**：能力清单有条目数与哈希锁，删条目/改条目会被完整性检查拦截。
5. **互斥自愈**：看门狗用命名互斥量防并发；重复实例退出，不重复拉起服务。

## 4. 失败模式与处置

| 失败 | 表现 | 处置 |
|---|---|---|
| 云端欠费/限流 | 401/402/403/429 | 标记 provider 冷却，切下一家；全挂走本地 |
| 云端挂起 | 超时 | 单家超时后切下一家，不无限等待 |
| 模型“假成功” | 声称完成但无变化 | 证据闸门直接判失败，记录 NO_EVIDENCE |
| 看门狗并发 | 多个实例同时拉起 | 命名互斥量；重复实例退出 |
| 清单被改短 | 条目数/哈希不符 | MANIFEST_INTEGRITY_FAIL |
| 日志分散 | 无法回放 | trace_id 贯穿 ingress / gateway / executor / RPA |

## 5. 这个设计适合谁

- 已经在做 Agent，但被“看起来成功”和“日志考古”折磨的团队；
- 需要在本地执行、又不放心把执行权交给云端的场景；
- 想把“生成”和“验收”拆开，做可审计自动化的人。

## 6. 这个设计不适合谁

- 想要开箱即用 Agent 框架的人；
- 只需要一个聊天机器人的人；
- 不愿意为证据、trace、回滚付出工程成本的人。

## 7. 未开源部分

核心执行器、本地 RPA、宿主适配层、凭据管理不在本仓库内。这里只公开结构与设计取舍。
